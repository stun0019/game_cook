# 《灶腳大亂鬥》商用垂直切片驗收規格

## 1. 文件目的

本文件把 `COMMERCIAL_ROADMAP.md` 的 M2、M4、M5 轉成可直接實作與逐項判定 Pass／Fail 的第一關規格。驗收對象為 16:9 單人 Web 版垂直切片，不包含大量關卡、帳號、雲端存檔或排行榜。

規格優先順序：本文件 > `COMMERCIAL_ROADMAP.md` 第 5 節 > 目前原型行為。若程式與本文件不同，以本文件作為垂直切片出貨目標。

## 2. 規格矛盾與統一決議

路線圖早期版本曾定義「第一單先做番茄堡，組裝台預放麵包」，第三階段則改為「開始時手持完成的試吃漢堡，只需移動與出餐」。目前 `index.html` 實作仍採前者。

**統一採用：手持完成試吃漢堡的一鍵出餐版。**

理由：它在 8 秒內完整教會移動、接近判定與情境互動鍵，先提供一次明確成功，再逐步加入拿取、組裝與加工；比預放麵包版少至少 6 次互動，也不需要玩家在首次操作前閱讀食譜。試吃單計入分數、完成單數與星級，送達後才開始 60 秒正式倒數。

## 4. 第一關狀態機

### 4.1 頂層狀態

```text
BOOT
  └─資源與存檔就緒→ TITLE
TITLE
  └─開始→ TUTORIAL_DELIVERY
TUTORIAL_DELIVERY
  └─試吃單成功→ PLAY_INTRO（啟動 60 秒）
PLAY_INTRO
  └─第三單成功→ PLAY_ACTIVE
PLAY_INTRO／PLAY_ACTIVE
  ├─手動暫停或失焦→ PAUSED
  ├─時間歸零且符合最後上菜→ FINAL_GRACE
  └─時間歸零且不符合→ RESULT
PAUSED
  └─玩家按繼續→ 暫停前狀態
FINAL_GRACE
  ├─成功送餐→ RESULT
  └─5 秒歸零→ RESULT
RESULT
  ├─再玩一次→ TUTORIAL_DELIVERY
  ├─下一關→ 第二關 TITLE
  └─返回選關→ LEVEL_SELECT
```

### 4.2 狀態定義與進入條件

| 狀態 | 進入時必做 | 允許輸入 | 離開條件 |
|---|---|---|---|
| `BOOT` | 載入必要素材、驗證存檔、套用設定 | 無 | 必要素材成功或採替代素材後進入 `TITLE` |
| `TITLE` | 顯示開始、設定；停止遊戲時鐘與加工 | 選單 | 按開始 |
| `TUTORIAL_DELIVERY` | `time=60` 但不計時；玩家手持正確完成餐點；只生成試吃單；高亮出餐口 | 移動、出餐、暫停 | 正確出餐 |
| `PLAY_INTRO` | 計時起跑；依序生成第二、第三單；一次只顯示當前單 | 全部遊戲操作、暫停 | 第三單成功或時間歸零 |
| `PLAY_ACTIVE` | 啟用下一單預覽，維持最多 2 張固定簡單單 | 全部遊戲操作、暫停 | 時間歸零 |
| `PAUSED` | 凍結時鐘、耐心、加工、動畫邏輯及音訊；記住來源狀態與暫停原因 | 繼續、設定、離開 | 玩家主動按繼續，不可因重新聚焦自動恢復 |
| `FINAL_GRACE` | 顯示 5 秒；停止生成訂單、停止一般關卡倒數；僅保留目前可送出的成品 | 移動、出餐 | 送餐成功或 5 秒結束 |
| `RESULT` | 只執行一次結算與存檔；停止所有遊戲工作與音訊 | 重試、下一關、選關 | 玩家選擇 |

### 4.3 必須保持的狀態不變量

- 任一時刻只能有一個頂層狀態。
- `RESULT` 出現後，分數、星數與完成單數不可再改變。
- 每局具唯一 `runId`；非目前 `runId` 的加工完成、出餐動畫或延遲工作不得回寫狀態。
- 玩家最多手持一個物品；物品不能同時存在於手上與工作台。
- 訂單陣列不可為空：剩餘 10 秒停止補單後例外，允許玩家完成現有單並等待結束。
- 第一關分數永不低於 0，且沒有任何扣分路徑。
- 所有時間以單一單調時鐘計算，不得同時混用會在背景繼續執行的獨立計時器。

## 5. 第一關 60 秒節奏與固定訂單

### 5.1 教學前試吃單

```text
recipeId: tutorial_ready_burger
初始 held: burger
初始 heldRecipe: [bun, cookedMeat]
初始位置: 出餐口可在 3 秒內到達的位置，角色面向出餐口
訂單耐心: 隱藏且不下降
操作: 移動 → 出餐口互動
獎勵: 100 分、完成數 +1、星級條到 1 星
成功後: 播放回饋，再啟動 60 秒倒數
```

- 3 秒未移動：顯示通往出餐口的路徑光點。
- 6 秒未成功：出餐口與互動鍵各放大一次，提示「把手上的漢堡送到鈴鐺」。
- 不自動完成、不扣分、不啟動倒數，也不顯示其他訂單。

### 5.2 正式 60 秒

| 剩餘時間／階段 | 訂單與教學 | 系統限制 |
|---|---|---|
| 60–45 秒 | 第二單 `ready_meat_burger`：取麵包、取現成肉排、依序放入組裝台；材料齊全即自動成餐，再出餐 | 只顯示 1 單；肉排成品盤高亮；無耐心下降 |
| 45–25 秒 | 第三單 `cooked_meat_burger`：取生肉、啟動煎鍋、加工 1.5 秒；加工時引導先拿麵包 | 只顯示 1 單；角色可自由移動；無耐心下降 |
| 25–10 秒 | 依序 `tomato_burger`、`meat_burger` 交替；第三單完成後才顯示下一單預覽 | 最多 2 單；僅當前單耐心下降 2 點／秒，歸零後保留訂單 |
| 10–0 秒 | 不再補新單；已存在訂單與加工可完成 | 10 秒提示一次，5 秒起每秒脈衝；不新增豪華堡 |

時間帶是目標節奏，不得強制跳過玩家尚未完成的教學單；第二、第三單以完成事件推進。若第三單在剩餘 25 秒後才完成，直接進入固定簡單單階段；若到剩餘 10 秒仍未完成，保留目前訂單但不再補單。

固定序列為：`tutorial_ready_burger` → `ready_meat_burger` → `cooked_meat_burger` → `tomato_burger` → `meat_burger`，其後只交替番茄堡與肉排堡。第一關不得出現豪華堡或隨機食譜。

### 5.3 第一關分數與星級

```text
正確出餐基礎分 = 100
速度加分 = clamp(0, 50, round(剩餘耐心 × 0.5))
連擊加分 = 第 1 單 0；第 2 單 25；第 3 單起 50
首次完成加工教學 = 25（每局最多一次）
錯誤、拆解、丟棄、耐心歸零 = 0 分變動
星級門檻 = 1 星 100；2 星 350；3 星 600
```

- 試吃單保證可取得 1 星；第一關目標是建立信心，不以第一次失敗阻擋後續內容。
- 耐心歸零只令該單速度加分為 0，並重置連擊；訂單不離開，分數不下降。
- 連擊「火熱手感」在連續 3 單成功後啟動 6 秒：移速 +10%、得分倍率 1.25、音樂增加一層；暫停期間不消耗時間。

## 6. 第一關不扣分、不跑單規則

| 情境 | 必須行為 | 禁止行為 |
|---|---|---|
| 耐心歸零 | 訂單留在第一順位；耐心顯示為空；速度加分歸零；連擊歸零 | 移除訂單、扣分、顯示客人離開 |
| 拿錯原料到加工台 | 原料保留在手上；工作台輕彈拒收；高亮正確台 | 銷毀原料、扣分、鎖控制 |
| 放入訂單不需要的材料 | 組裝台拒收並將材料彈回手上；訂單閃爍需要的材料 | 污染整盤、扣分、強迫丟棄 |
| 重複放入相同材料 | 材料留在手上並提示「已經有了」 | 吞掉材料或形成無法修復餐點 |
| 完成錯誤餐點 | 原則上應由組裝驗證阻止；若仍發生，出餐口拒收並保留餐點 | 扣分、銷毀餐點、跳過當前單 |
| 想改做法 | 在組裝台按「拆解」將餐點還原為材料；材料暫存在組裝台 | 只能丟棄重做 |
| 丟棄 | 清除手持物並二次短按確認稀有／完成品；不影響分數 | 重置連擊或扣分 |

連續 8 秒沒有有效進度時，依序啟用下一工作台高亮、路徑光點、單句動作提示。有效進度定義為正確拿取、工作台接受材料、加工完成、正確組裝或出餐。

## 7. 暫停與失焦

### 7.1 手動暫停

- `PLAY_INTRO`、`PLAY_ACTIVE`、`FINAL_GRACE` 必須提供暫停鍵；鍵盤 `Escape` 同樣有效。
- 進入 `PAUSED` 後凍結關卡剩餘時間、最後上菜時間、耐心、加工剩餘時間、火熱手感、遊戲動畫邏輯與震動。
- 音樂在 150–300 毫秒內淡出暫停，循環音效立即停止；UI 按鍵音仍可播放。
- 暫停畫面提供：繼續、音效／音樂／震動／減少動態設定、重新開始、返回標題。
- 重新開始與返回標題需二次確認；繼續後給 1 秒「準備」遮罩，再恢復所有時鐘。

### 7.2 失焦與背景

- 監聽 `visibilitychange`、`pagehide`、`blur`；任一事件發生且正在遊戲時，立即以 `reason=background` 進入 `PAUSED`。
- `focus` 或回到可見狀態不可自動恢復，必須由玩家按「繼續」。
- 暫停時保存每個加工工作的 `remainingMs`；不得讓背景中的 `setTimeout` 直接完成食材。
- 重複收到失焦事件只暫停一次；不得疊加遮罩或重複保存。
- 若在 0 秒判定與失焦同幀發生，先依狀態機決定 `FINAL_GRACE` 或 `RESULT`，結果不可因恢復焦點而重算。

## 8. 音效、音樂與震動設定

### 8.1 必要音訊事件

| 事件 | 聲音目的 | 限制 |
|---|---|---|
| 移動 | 輕腳步確認速度 | 同一聲音至少間隔 180 ms，停止即停 |
| 拿取／放下 | 確認物品歸屬已改變 | 判定成功後 100 ms 內播放 |
| 加工開始／循環／完成 | 區分已接受、進行中、可以拿取 | 循環最多同時一軌；暫停與離台不殘留 |
| 錯誤 | 提醒可修正，不製造懲罰感 | 短而低音量，150 ms 內不得重複觸發 |
| 正確出餐 | 本局最強的單次成功確認 | 與分數飛字同時開始，延遲 ≤100 ms |
| 連擊／火熱手感 | 音高逐級增加，提示獎勵升級 | 不蓋過加工完成提示 |
| 倒數 | 10 秒提示、5 秒起節拍 | 10 秒前不得播放警報音 |
| 暫停／結算 | 明確區分流程狀態 | 結算音只播放一次 |

### 8.2 設定行為

- `musicVolume`：0–1，預設 0.7；`sfxVolume`：0–1，預設 0.8。
- `muted`：預設 `false`，一鍵靜音但保留原音量值。
- `vibration`：支援 `navigator.vibrate` 時預設 `true`；不支援時隱藏選項，不視為錯誤。
- `reduceMotion`：`system | on | off`，預設 `system`；需覆寫現有只讀系統偏好的行為。
- 第一次使用者手勢才建立／恢復音訊環境；瀏覽器禁止自動播放時不得卡住遊戲。
- 所有設定變更立即生效並寫入存檔；靜音後不得仍有循環音、倒數音或背景分頁音訊。

### 8.3 震動規格

```text
拿取成功: 10 ms
加工完成: 20 ms
正確出餐: [20, 25, 35]
錯誤拒收: [25, 30, 25]
最後 3 秒: 每秒 15 ms
```

- 震動只輔助視覺／音效，不得成為唯一提示。
- 全域震動呼叫至少間隔 120 ms；暫停、失焦、設定關閉或減少動態開啟時停止尚未完成的震動序列。

## 9. 可見介面與八方向柴犬主廚

### 9.1 全畫面 Emoji 禁用

玩家可見介面禁止使用系統 Emoji，包括但不限於：HUD 圖示、食材、訂單、按鈕、教學、提示、分數、星級、倒數、旋轉裝置畫面、錯誤 fallback、CSS `content`、Canvas 文字及 SVG `<text>`。

允許內容只有：

- 一般繁體中文字、阿拉伯數字與必要標點。
- 以 `<img>`、內嵌 `<svg>` 或 CSS mask 呈現的專案原創 SVG。
- 無障礙名稱使用純文字，例如「星級」、「剩餘時間」、「番茄」，不得用 Emoji 代替名稱。

以下均判定失敗：

- 圖片載入失敗時退回 `🍅`、`🍔` 等字元。
- 以 `⭐`、`⏱`、`📱` 等字元作為 HUD 或提示圖示。
- SVG 內嵌 Emoji 字型文字，或依賴作業系統彩色 Emoji 呈現。
- Emoji 被 CSS 隱藏但仍可能在載入、錯誤、減少動態或無樣式狀態下顯示。

**驗收方式**

1. 掃描正式執行所需的 HTML、CSS、JavaScript、SVG（不含企劃文件）中的 Unicode Emoji／Extended Pictographic 字元；玩家可見字串命中數必須為 0。
2. 在所有正式 SVG 載入成功、逐一載入失敗、停用 CSS、開啟減少動態四種狀態下完成全流程截圖；畫面不得出現系統 Emoji 或缺圖 Emoji fallback。
3. 檢查 DOM 文字節點、表單值、`alt`／`aria-label`、CSS 偽元素與動態 toast；語意皆使用純文字。
4. Windows、macOS、iOS、Android 各抽測一次，畫面不得因不同系統 Emoji 字型而改變。

### 9.2 原創 SVG 替代清單

| 類別 | 必要原創 SVG | 驗收條件 |
|---|---|---|
| HUD | 星級、計時器、暫停、音樂、音效、震動、返回 | 同一圖示採一致描邊與色票；16 px 顯示仍可辨識 |
| 食材／餐點 | 麵包、生番茄、切片番茄、生肉、熟肉、完成漢堡 | 生／熟及完整／加工後不得只靠色彩區別 |
| 工作台 | 原料箱、砧板、煎鍋、組裝盤、出餐鈴、垃圾桶 | 圖示與實際互動類型一致；不可用文字圖符代替 |
| 教學／狀態 | 移動、方向箭頭、互動、完成、錯誤、連擊、旋轉裝置 | 每個狀態有文字備援，但不使用 Emoji |
| 角色 | 柴犬主廚 8 方向、手持與動作狀態 | 共用相同骨架尺寸與腳底錨點，切換不位移 |

- 所有 SVG 必須是專案原創或具明確商用權利；每項納入素材授權清冊。
- SVG 不得引用外部字型、遠端圖片或第三方 Emoji 圖庫。
- 食材載入失敗時以純文字名稱與通用輪廓 placeholder 顯示，不得退回 Emoji。
- SVG 應具固定 `viewBox`、合理 `aria-hidden`／可存取名稱，裝飾圖不得重複朗讀。

### 9.3 柴犬主廚八方向資產與切換

方向資產固定為：

```text
chef-shiba-n.svg
chef-shiba-ne.svg
chef-shiba-e.svg
chef-shiba-se.svg
chef-shiba-s.svg
chef-shiba-sw.svg
chef-shiba-w.svg
chef-shiba-nw.svg
```

- N 為背面、S 為正面、E／W 為側面，其餘為前／後四分之三視角；耳朵、尾巴、帽子與圍裙必須維持同一角色辨識特徵。
- 八份正式輸出需共用相同 `viewBox`、腳底中心錨點與視覺高度；可由原創基礎稿鏡像製作，但正式檔案與方向映射必須各自存在並通過手持物檢查。
- 預設朝向為 S。只有有效移動向量能改變朝向；停止、暫停、碰牆或輸入回到死區時保留最後朝向。
- 方向切換只替換角色視圖，不得重設移動、動畫進度、手持物、碰撞範圍或工作台接近判定。

方向量化採畫面座標（右為正 X、下為正 Y）：

| 輸入角度 `atan2(y,x)` | 朝向 |
|---|---|
| -22.5°～22.5° | E |
| 22.5°～67.5° | SE |
| 67.5°～112.5° | S |
| 112.5°～157.5° | SW |
| ≥157.5° 或 <-157.5° | W |
| -157.5°～-112.5° | NW |
| -112.5°～-67.5° | N |
| -67.5°～-22.5° | NE |

邊界角度採順時針區段；例如恰為 22.5° 判定 SE，避免不同輸入裝置產生不一致結果。

### 9.4 停止保留朝向與方向抖動防止

- 搖桿輸入長度 `<0.18` 視為死區：角色停止且不更新朝向。
- 已有朝向時，新向量必須跨過原區段邊界至少 7.5°，並持續 60 ms，才切換到相鄰方向。
- 若新向量直接跨越兩個以上區段且長度 `≥0.55`，立即切換，不等待 60 ms，避免快速反向顯得遲鈍。
- 數位鍵盤輸入不使用 60 ms 等待：有效單鍵或雙鍵組合立即切換；相反鍵同時按下時該軸為 0，若總向量為 0 則保留朝向。
- 角色碰到邊界但玩家仍持續輸入時，保留輸入方向；放開後仍保留該方向。
- 每次切換資產後腳底中心位移不得超過 2 CSS px，角色外框不得造成碰撞或鏡頭抖動。

### 9.5 手持物位置與遮擋

手持物使用角色 `viewBox` 的百分比錨點，原點為左上。以下為預設中心點；美術可在 ±3% 內微調，但必須通過雙掌接觸驗收。

| 朝向 | 手持中心 `(x,y)` | 圖層 | 目的 |
|---|---|---|---|
| N | (50%, 48%) | 身體後方、手臂前方 | 從背面只露出合理上緣，不穿過帽子 |
| NE | (58%, 50%) | 身體後方、近側手臂前方 | 配合後四分之三視角 |
| E | (63%, 54%) | 身體前方 | 物品在前伸雙掌，不遮整張臉 |
| SE | (58%, 58%) | 身體前方 | 配合前四分之三視角 |
| S | (50%, 60%) | 身體前方 | 置於胸前雙掌之間 |
| SW | (42%, 58%) | 身體前方 | 與 SE 對稱且不漂移 |
| W | (37%, 54%) | 身體前方 | 與 E 對稱且位於移動前方 |
| NW | (42%, 50%) | 身體後方、近側手臂前方 | 與 NE 對稱 |

- 食材最大寬度為角色 `viewBox` 寬度的 42%，最大高度 30%；完成漢堡可放大至 46%，但不得遮住雙眼超過 20%。
- 切換相鄰方向時，手持物在 80–120 ms 內移至新錨點；減少動態模式立即切換。
- 手持物錨點只影響顯示，不影響碰撞、送餐距離或物品狀態。
- 空手時不得保留透明手持節點攔截輸入；載入失敗使用純文字食材名稱，不使用 Emoji。

### 9.7 連續 U 型餐廳流理台

#### 空間與動線

廚房工作區必須是下方開口的連續 U 型流理台，角色在 U 型內側活動。站點配置固定遵循以下工作流：

```text
左側直向檯面：備料區
  麵包 → 番茄 → 生肉

上側橫向檯面：加工區
  砧板 → 煎鍋 → 現成品／暫放區

右側直向檯面：完成區
  組裝台 → 出餐口 → 垃圾／拆解區

主要動線：左側取料 → 上側加工 → 右側組裝與出餐
角色活動區：U 型內側與下方開口，不得站到櫥櫃上或穿越檯面
```

- 左、上、右三段檯面在兩個轉角實際連接；不得用三組互不相連的卡片、浮島或僅靠相近位置假裝相連。
- 玩家可從下方開口進入 U 型內側；內側所有必要站點都能沿連續走道到達。
- 第一關主流程不得要求角色繞到 U 型外側；外側不放置必要互動物。
- 相鄰任兩個主流程站點之間的最短可走路徑不得經過觸控控制區，也不得窄於角色碰撞直徑的 1.4 倍。

#### 建議比例與安全區

以下百分比以 HUD 下方的 `kitchenSafeArea` 為基準，不是整個瀏覽器視窗：

| 區塊 | 建議範圍 | 必要條件 |
|---|---|---|
| 上側檯面 | `x: 8%–92%`, `y: 4%–25%` | 左右端與兩側檯面無縫相接 |
| 左側檯面 | `x: 8%–24%`, `y: 4%–74%` | 由上而下嵌入麵包、番茄、生肉 |
| 右側檯面 | `x: 76%–92%`, `y: 4%–74%` | 由上而下嵌入組裝、出餐、垃圾／拆解 |
| 內側活動區 | `x: 24%–76%`, `y: 25%–92%` | 保持連續可走，不被裝飾物切斷 |
| 下方開口 | `x: 24%–76%`, `y: 74%–100%` | 不設檯面，保留角色進出與教學空間 |

比例可依實機微調，但不得破壞 U 型辨識、工作流順序或控制區零遮擋。桌面超寬時以置中的 16:9 安全框布局，不得把左右檯面拉到彼此距離過遠。

#### 連續檯面與櫥櫃視覺

- 三段共用同一檯面材質、前緣厚度、透視方向、櫥櫃高度、踢腳板與陰影系統。
- 轉角必須有專用內／外角連接件；檯面前緣、背板、櫃門基線與踢腳板在轉角處連續，1× 顯示下不可見超過 2 CSS px 的裂縫。
- 櫥櫃門、抽屜及把手屬於連續底櫃，不得每個工作站各自擁有完整卡片邊框、獨立大陰影或四面描邊。
- U 型輪廓需在關閉站點高亮、動畫與提示後仍能一眼辨認；不可依靠黃色外框才看出相連。
- 地板與檯面需有清楚深度關係，角色腳底不得視覺上漂到檯面前緣或底櫃之上。

#### 嵌入式站點

- 原料盒、砧板、煎鍋、組裝盤與出餐鈴均嵌在連續檯面表面；站點可有局部凹槽、爐框或材質差異，但不可呈現成獨立浮動卡片。
- 站點視覺邊界與互動 hit area 分離：SVG 可不規則，但互動區需為穩定矩形或多邊形，並隨響應式布局同步更新。
- 玩家進入互動距離時，只高亮檯面內的設備與對應純文字標籤，不高亮整段櫥櫃。
- 同時落入多個 hit area 時只選距離最近者；目標切換需符合 100 ms 回饋門檻，且不可因相鄰站點交界每幀抖動。
- 工作站即使沒有卡片外框，首次玩家仍須能依原創 SVG、檯面嵌入造型、標籤及鄰近高亮辨識功能。

#### 角色內側活動與碰撞

- 角色碰撞以固定腳底圓或膠囊為準，不隨柴犬方向 SVG 外框改變。
- 左、上、右檯面形成一組連續不可穿越碰撞；兩個轉角不得有可鑽出的縫，也不得形成看得見卻走不過的隱形尖角。
- 角色與檯面互動時停在內側前緣；八方向朝向應自然面向站點，無需踏入或穿過檯面。
- 內側活動區至少能容納角色迴轉與持物動畫；任何位置都可在不穿越檯面的情況下回到下方開口。
- 出生點、教學路徑、最後上菜路徑與重試重生點均位於內側合法區域。

#### 控制區零遮擋

- 觸控搖桿、互動、丟棄與暫停按鈕的可見矩形加 8 CSS px 安全邊，不得與任何站點圖示、站點標籤、互動 hit area、訂單、倒數或必要提示相交。
- 觸控控制可以覆蓋非必要地板，但該區不得成為任兩個必要站點之間的唯一通路；角色不需走入控制下方才能完成第一關。
- 桌面使用鍵盤時可降低觸控控制透明度或隱藏，但隱藏後不得改變 U 型檯面、站點或碰撞位置。
- 手機安全區 `env(safe-area-inset-*)` 必須加入控制位置計算；瀏海、系統手勢區及瀏覽器工具列不得壓住控制或右側出餐區。

## 10. localStorage 資料格式

### 10.1 儲存鍵與 JSON

儲存鍵固定為 `stove-brawl.save.v1`。不保存進行中的單局，以避免計時與加工狀態不一致。

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-08-02T12:00:00.000Z",
  "progress": {
    "unlockedLevel": 2,
    "tutorialCompleted": true,
    "levelStars": { "1": 3 },
    "bestScore": { "1": 725 },
    "bestCombo": { "1": 4 }
  },
  "settings": {
    "musicVolume": 0.7,
    "sfxVolume": 0.8,
    "muted": false,
    "vibration": true,
    "reduceMotion": "system",
    "language": "zh-Hant"
  }
}
```

### 10.2 讀寫規則

- 在 `BOOT` 讀取一次；設定變更及 `RESULT` 結算後寫入。
- 星數、分數、連擊只保存歷史最高值，不得以較低新成績覆寫。
- 所有數字需檢查有限值並夾在合法範圍；未知欄位忽略，缺少欄位補預設值。
- JSON 損壞、型別錯誤、未知 `schemaVersion`、無痕模式或瀏覽器拒絕儲存時，使用記憶體預設值繼續遊戲，不顯示阻斷性錯誤。
- 寫入失敗最多提示一次「本次進度可能無法保存」；不得每次互動重複提示。
- `updatedAt` 僅作除錯與遷移，不作玩家追蹤；不得加入姓名、郵件、精確位置、裝置指紋或廣告識別碼。
- 未來版本以 `schemaVersion` 遷移；遷移失敗回復預設值並保留可診斷錯誤，不覆寫原字串直到新存檔成功。

## 11. 結算與重試

### 11.1 結算內容

- 依序顯示獲得星星、總分、完成訂單數、最快一單、最高連擊。
- 0 星只可能發生在玩家離開試吃教學前主動返回；正常完成試吃單即至少 1 星。
- 顯示一則可執行建議，優先順序：卡住步骤 > 錯誤操作最多的工作台 > 未利用加工時間 > 鼓勵挑戰下一星。
- `再玩一次` 與已解鎖的 `前往第二天` 在結算開始後 2 秒內可操作；另提供返回選關。
- 結算、解鎖與存檔必須冪等，同一局即使重複收到結束事件也只執行一次。

### 11.2 重試重設範圍

按下重試後必須：

1. 增加 `runId`，取消或令舊局的計時器、加工工作、動畫回呼及震動失效。
2. 清空手持物、組裝台、加工台、訂單、分數、連擊、提示與暫停來源。
3. 回到 `TUTORIAL_DELIVERY`，設置完成試吃漢堡及單一試吃單；正式倒數保持 60。
4. 保留玩家設定與已存最高紀錄，但本局 HUD 歸零。

## 13. 商用垂直切片出貨門檻

### 13.1 功能與內容

- 本文件第 4–12 節所有必要規則實作完成，E01–E29、D01–D18 與 L01–L14 全部通過。
- 從標題、試吃單、60 秒遊戲、最後上菜、結算、重試到下一關入口均可完整走通。
- 第一關沒有任何扣分、跑單、隨機豪華堡或無法修正的錯餐路徑。
- 玩家可見畫面 Emoji 數量為 0；正式圖示與柴犬主廚均為已登錄授權的原創 SVG。
- 柴犬主廚八方向、停止保留朝向、方向防抖與八方向手持錨點全部通過錄影驗收。
- 廚房為視覺、碰撞與互動皆連續的 U 型流理台；不得存在獨立漂浮工作台卡片，桌面與手機控制區皆為零遮擋。
- P0 阻斷與 P1 重大問題均為 0；P2 問題均有明確是否接受的書面決議。

### 13.2 玩家驗收

- 至少 10 名未接觸版本的目標玩家參與；不得由測試主持人口頭教操作。
- 至少 9／10 在 8 秒內完成試吃單。
- 至少 8／10 在正式倒數前 20 秒內完成「拿取 → 組裝 → 出餐」。
- 首玩 0 單率低於 5%，首玩取得至少 1 星的比例不低於 80%。
- 至少 8／10 能不讀紀錄文字，辨認成功、加工中、加工完成與錯誤拒收。
- 至少 8／10 表示願意立即重試或進入第二關；若未達標，不得只靠降低門檻宣告通過，需記錄流失步驟並修正。

### 13.3 M4 聲畫與操作品質

- 每個核心操作在狀態成立後 100 ms 內有視覺或聲音回饋。
- 玩家能只靠原創 SVG、角色朝向與純文字辨識訂單、剩餘時間、星級、手持物與下一個互動目標。
- 音樂、音效、靜音、震動與減少動態設定立即生效並可跨重開保存。
- 靜音與減少動態模式仍能完成所有操作，沒有資訊只靠音效、顏色或震動表達。
- 連續遊玩 30 分鐘無音效堆疊、明顯削波、循環殘留或動畫遮蔽關鍵 UI。
- 所有正式圖片、音效、音樂與字體均有商用授權記錄。

### 13.4 M5 流程與可靠性

- 暫停期間倒數、耐心、加工、火熱手感與震動全部停止；失焦後不自動恢復。
- 關閉重開後，最高星數、解鎖及設定 100% 恢復；壞存檔與不可用儲存環境不阻斷遊戲。
- 重試 20 次、連玩 10 局後不存在重複計時器、跨局加工回呼、重複結算或持續成長的暫存節點。
- 結算後 2 秒內可重試或前往下一關，按重試後 500 ms 內可重新操作。

### 13.5 相容與效能

- 最新版與前一主要版 Chrome、Edge、Firefox、Safari 完成桌機冒煙測試；iOS Safari 與 Android Chrome 真機完成第一關全流程。
